# 갯바위 새벽 브리핑

저비스 베이 **리틀 비크로프트 헤드**를 기본으로, 갯바위 포인트의 **파고·너울·
물때**를 매일 아침 카카오톡으로 받습니다. **새벽 6시 입수**를 기준으로 계산하고,
토요일에 낚시를 나가시므로 평일 브리핑에는 다가오는 토요일 전망이 붙습니다.

```
[8/12(수)] 리틀 비크로프트 헤드
06시 파고 1.2m(세트 2.2m) 너울 1.0m/11s SE
물때 썰물, 간조 09:30
바람 SSW 15km/h · 일출 06:32
위험 · 너울 주기 11초
토(8/15) 위험 1.2m
※사격장 개방 확인 필수 (Range Control 4448 3839)
```

상세본은 세션 중 조건이 나빠지는 시점을 따로 짚어줍니다. 입수할 때 멀쩡하다가
아침나절에 커지는 경우가 갯바위에서 가장 곤란한 상황이라서입니다.

```
  파고     06시 유의 1.0m / 예상 최대 세트 1.9m
           09시 최악 2.4m (세트 4.5m)
```

---

## 먼저 알아두실 것

**이 코드는 실제 API 응답으로 검증되지 않았습니다.** 개발 환경의 네트워크가
차단되어 Open-Meteo를 한 번도 호출하지 못했습니다. 로직(조위 극값 계산, 위험도
판정, 포맷)은 합성 데이터로 전부 검증했지만, 실제 응답 형식은 아래 `selfcheck.py`
로 처음 한 번 확인해주셔야 합니다.

특히 불확실한 부분은 **조위 변수(`sea_level_height_msl`)가 이 좌표에서 실제로
제공되는지** 입니다. 안 나오면 물때 줄만 빠지고 나머지는 정상 동작합니다.

**그리고 이건 안전 판정이 아닙니다.** 예보 격자는 수 km 단위라 특정 갯바위의
너울 반사나 지형 증폭을 반영하지 못합니다. "양호"가 떠도 현장에서 세트를 직접
보고 판단하세요.

## 비크로프트 반도 출입 (파도보다 먼저 확인할 것)

리틀 비크로프트 헤드를 포함한 **비크로프트 반도 전체가 호주 국방부의
비크로프트 사격장(Beecroft Weapons Range) 구역**입니다. 파도와 무관하게 출입이
통제됩니다.

- **주말과 NSW 공휴일·방학에는 개방**합니다. 토요일 낚시는 대체로 문제없습니다.
- 다만 **군사 훈련·날씨·도로 사정으로 단기 통보 없이 닫힙니다.**
- 폐쇄 시 경계에 **붉은 깃발**과 안내판이 걸립니다.
- 출발 전 확인: **Range Control 4448 3839**
- [국방부 안내 페이지](https://www.defence.gov.au/about/locations-property/beecroft-weapons-range-peninsula)

브리핑 하단에 이 안내가 자동으로 붙고, 카카오톡 메시지에는 국방부 페이지로
바로 가는 버튼이 달립니다. 파고만 보고 내려갔다가 깃발 보고 돌아오는 일이
없도록 넣었습니다. 자동 확인은 불가능합니다 — 개방 여부가 API로 제공되지
않습니다.

## 데이터 출처와 해석

| 항목 | 출처 | 비고 |
|---|---|---|
| 파고·너울·주기·방향 | Open-Meteo Marine API | 무료, 키 불필요 |
| 조위 (물때) | 같은 API의 `sea_level_height_msl` | 시간별 값에서 극값을 역산 |
| 바람·돌풍 | Open-Meteo Forecast API | 무료, 키 불필요 |

윌리웨더를 쓰신다고 하셨는데, 윌리웨더는 **유료 API**라 개인 자동화에는 비용이
붙습니다. Open-Meteo는 같은 원본 모델(주로 ECMWF·GFS 파랑모델)을 무료로 제공해서
이쪽을 썼습니다. 수치가 윌리웨더와 몇 십 cm 다를 수 있는데, 모델과 격자 해상도
차이입니다. 눈으로 비교해보시고 차이가 크면 알려주세요.

### 두 가지 계산

**예상 최대 세트파 = 유의파고 × 1.86.** 유의파고는 상위 1/3 파도의 평균이라,
실제로 갯바위에서 사람을 쓸어가는 큰 세트는 그보다 훨씬 큽니다. 레일리 분포에서
3시간(약 1000파) 중 최대파 기대값이 유의파고의 1.86배입니다. 파고 1.5m 예보는
**3m 세트가 온다는 뜻**입니다.

**위험도는 주기에 가중을 크게 뒀습니다.** 같은 1.2m라도 8초 풍파와 13초 너울은
갯바위에서 완전히 다릅니다. 장주기 너울은 수심이 얕아지면서 급격히 서서, 평온해
보이던 곳에 갑자기 큰 물이 올라옵니다. 12초 이상이면 파고와 무관하게 등급이
올라갑니다.

### 새벽 6시 기준

입수 시각이 **06시**라서, 브리핑의 파고·너울·바람은 06시 값입니다. 위험도는
실제로 갯바위에 서 있는 **04~11시 구간의 최악 조건**으로 매깁니다. 오후에
너울이 커지는 건 이미 철수한 뒤라 등급에 넣지 않습니다.

**물때는 들물/썰물을 같이 표시합니다.** 06시에 들물이면 낚시하는 동안 자리가
잠기면서 퇴로가 끊길 수 있어서, 만조/간조 시각만으로는 부족합니다.

**일출 시각도 넣었습니다.** 겨울 저비스 베이는 일출이 07시에 가까워서, 06시
입수면 한 시간 가까이 어두운 상태로 갯바위를 오르게 됩니다. 브리핑에
"입수 후 N분간 어두움"으로 표시됩니다.

시각을 바꾸시려면 `spots.py`의 `SESSION_START_HOUR`와 `SESSION_WINDOW`를
고치면 됩니다.

## 설치

### 1단계 — 네트워크 접근 허용

클라우드 환경의 기본 네트워크 등급은 `Trusted`라 패키지 저장소와 GitHub 정도만
열려 있습니다. 기상·카카오 API는 막히므로 `Custom`으로 바꾸고 아래 4개 도메인을
추가해야 합니다.

```
marine-api.open-meteo.com     파고·너울·조위
api.open-meteo.com            바람
kauth.kakao.com               카카오 토큰 갱신
kapi.kakao.com                카카오 메시지 전송
```

**설정 위치**: [claude.ai/code](https://claude.ai/code) → 메시지 입력창 바로 위
줄의 환경 이름 버튼(처음이면 `Default`) → 환경 위에 마우스를 올리면 나타나는
**톱니바퀴 아이콘** → 다이얼로그의 **Network access**를 `Custom`으로 변경.

자세한 내용은 [클라우드 환경 설정 문서](https://code.claude.com/docs/en/cloud-environments)를
참고하세요.

### 2단계 — 카카오 토큰 준비

`tools/kakao-notify/README.md` 대로 **내 컴퓨터에서** 한 번 인증하세요.
OAuth는 브라우저와 localhost 콜백이 필요해서 클라우드에서는 못 합니다.

```bash
cd tools/kakao-notify
python3 kakao_auth.py
```

인증이 끝나면 **등록할 내용이 화면에 그대로 출력됩니다.** 나중에 다시 보려면:

```bash
python3 kakao_auth.py --show-env
```

```
====================================================================
아래 두 줄을 환경변수로 등록하세요 (그대로 복사).
====================================================================
KAKAO_REST_API_KEY=abc123...
KAKAO_REFRESH_TOKEN=RT-xxxx...
====================================================================
```

이 두 줄을 1단계와 **같은 다이얼로그**의 **Environment variables** 칸에 `.env`
형식으로 넣으면 됩니다. 토큰 파일을 클라우드로 옮길 필요는 없습니다.

> **주의.** 공식 문서는 클라우드 환경변수에 자격증명을 넣지 말라고 명시합니다
> (비밀 저장소가 따로 없음). 이 토큰은 권한이 `talk_message` 하나뿐이라 유출돼도
> 본인에게 카톡을 보내는 것 외에는 못 하지만, 자격증명을 두고 싶지 않으시면
> **로컬 cron**으로 돌리는 편이 안전합니다. 판단 근거는
> `tools/kakao-notify/README.md`의 "클라우드 환경변수에 넣기 전에"를 보세요.

### 3단계 — 점검

```bash
cd tools/surf-brief
pip install -r requirements.txt
python3 selfcheck.py wollongong
```

도메인 4개, API 응답 형식, 브리핑 생성, 카카오 인증을 순서대로 확인하고
어디서 막혔는지 알려줍니다.

### 4단계 — 매일 자동 실행

점검이 통과하면 Claude에게 이렇게 말씀하시면 Routine을 만들어 드립니다.

> "브리핑 Routine 만들어줘"

직접 만드실 경우 cron 식은 아래와 같습니다(**UTC 기준**).

```
0 18 * * *      → 시드니 04:00 (AEST, 겨울) / 05:00 (AEDT, 서머타임)
```

**06시 입수라면 브리핑이 04시에 와야 의미가 있습니다.** 준비하고 이동할 시간이
남아야 하니까요. 다만 이건 **저비스 베이 근처에 계실 때** 기준입니다. 시드니에서
출발하시면 리틀 비크로프트까지 2시간 반 넘게 걸려서 03시쯤 나서야 하는데,
그러면 04시 브리핑은 이미 늦습니다. 그 경우 **전날 저녁**으로 바꾸는 게 맞습니다.

```
0 10 * * *      → 시드니 20:00, 다음날 새벽 세션을 미리 받음
```

> NSW는 10월 첫 일요일부터 4월 첫 일요일까지 서머타임이라, UTC 고정 cron은
> 연 2회 한 시간씩 밀립니다. 정확히 맞추시려면 서머타임 전환 때 말씀해주세요.

## 사용법

```bash
python3 surf_brief.py                      # 오늘 브리핑 (상세, 화면 출력)
python3 surf_brief.py --compact            # 카카오톡용 요약본 미리보기
python3 surf_brief.py --send               # 카카오톡으로 전송
python3 surf_brief.py --spot basspoint     # 포인트 지정
python3 surf_brief.py --date 2026-08-15    # 특정 날짜 (7일 예보 범위 내)
```

| `stanwell` | 스탠웰 파크 | `basspoint` | 베이스 포인트 (셸하버) |
| `coalcliff` | 콜클리프 | | |

> **좌표 정확도 주의.** 리틀 비크로프트 헤드는 `-35.0064, 150.8474`로 잡았습니다.
> 윌리웨더 지도에서 표시해주신 마커를 커라롱(`-35.0122, 150.8264`) 기준으로
> 화면 축척에서 역산한 값이라 **500m~1km 오차가 있을 수 있습니다.**
>
> 더 정확히 맞추시려면 구글 지도에서 실제 진입 지점을 우클릭(폰은 길게 누르기)
> 하면 좌표가 나옵니다. 알려주시거나, `spots.py`의 해당 줄을 직접 고치셔도 됩니다.
>
> **너울 노출 방향은 `10°~150°`로 잡았습니다.** 반도 북동쪽 모서리라 N~SE
> 너울에는 열려 있고, NSW 주력 너울인 S 계열은 반도 몸통에 가려진다고 보았습니다.
> 남너울이 크게 들어오는 날 이 자리가 상대적으로 잔잔하다면 맞게 잡은 것이고,
> 실제로는 남너울도 돌아 들어온다면 알려주세요 — 위험도 판정이 달라집니다.

## 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| `요청 실패` / `ConnectionError` | 네트워크 정책에 도메인이 안 열렸습니다. 1단계를 확인하세요. |
| `selfcheck`에서 `sea_level_height_msl 값 없음` | 해당 좌표에 조위 데이터가 없습니다. 물때 줄만 빠지고 나머지는 동작합니다. 다른 조석 소스가 필요하면 알려주세요. |
| `저장된 토큰이 없습니다` | `KAKAO_REFRESH_TOKEN` 환경변수가 비었습니다. 2단계를 확인하세요. |
| `액세스 토큰 갱신 실패` | 리프레시 토큰 만료(2개월 미사용). 로컬에서 `kakao_auth.py`를 다시 실행하고 새 토큰으로 교체하세요. |
| `예보 범위 밖입니다` | Open-Meteo 무료 예보는 7일까지입니다. |
| 요약본이 잘림 | 200자를 넘었습니다. `format_compact`에서 항목을 줄이세요. |
