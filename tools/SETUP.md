# 처음부터 끝까지 — 갯바위 브리핑 설치 순서

컴퓨터 앞에서 위에서부터 순서대로 하시면 됩니다. 전부 40분쯤 걸립니다.

**순서가 중요합니다.** 3부에서 데이터가 쓸 만한지 먼저 확인하고, 그게 통과한
뒤에 클라우드 설정으로 넘어갑니다. 반대로 하면 설정을 다 끝내놓고 정작 파고
수치가 안 맞는 걸 그때 발견하게 됩니다.

- [1부. 카카오 개발자 앱 만들기](#1부-카카오-개발자-앱-만들기) (약 10분, 브라우저)
- [2부. 내려받기와 인증](#2부-내려받기와-인증) (약 10분, 터미널)
- [3부. 데이터 검증](#3부-데이터-검증) ← **여기서 판단** (약 5분)
- [4부. 클라우드 설정](#4부-클라우드-설정) (약 10분, 브라우저)
- [5부. 자동 실행 걸기](#5부-자동-실행-걸기) (제가 합니다)

## 1부. 카카오 개발자 앱 만들기

[developers.kakao.com](https://developers.kakao.com) 로그인 후:

1. **내 애플리케이션** → **애플리케이션 추가하기** → 앱 이름과 회사명 입력
   (개인이면 본인 이름을 넣으셔도 됩니다)
2. **앱 설정 → 앱 키** → **REST API 키** 복사해서 메모장에 붙여두기
3. **제품 설정 → 카카오 로그인** → 활성화 설정 **ON**
4. 같은 화면의 **Redirect URI** 에 정확히 이 주소를 등록

   ```
   http://localhost:5000/oauth
   ```

5. **제품 설정 → 카카오 로그인 → 동의항목** → **카카오톡 메시지 전송**
   (`talk_message`) 을 **선택 동의**로 설정

> 4번 주소는 글자 하나까지 같아야 합니다. 뒤에 `/`가 붙거나 포트가 다르면
> 인증할 때 `KOE006` 오류가 납니다.

## 2부. 내려받기와 인증

터미널에서:

```bash
git clone --depth 1 -b claude/mail-kakao-permissions-6uzf6b \
  https://github.com/ghrms2014-rgb/first-contributions
cd first-contributions/tools/kakao-notify
pip install -r requirements.txt
```

REST API 키를 설정에 넣습니다.

```bash
cp .env.example .env
```

`.env` 를 편집기로 열어 1부 2번에서 복사한 키를 붙여넣으세요.

```
KAKAO_REST_API_KEY=여기에_복사한_키
```

인증합니다. 브라우저가 열리면 카카오 로그인 후 동의하면 끝입니다.

```bash
python3 kakao_auth.py
```

바로 확인해보세요. 카톡이 오면 성공입니다.

```bash
python3 kakao_notify.py "테스트"
```

> **Windows**: `python3` 대신 `python`, `cp` 대신 `copy` 를 쓰세요.
> 브라우저가 안 열리면 `python3 kakao_auth.py --manual` 로 하시면 됩니다.

## 3부. 데이터 검증

**여기가 제일 중요합니다.** 이 저장소는 외부 네트워크가 막힌 환경에서 만들어져서,
기상 API를 한 번도 실제로 호출해보지 못했습니다. 사용자님 컴퓨터에서 처음
확인하시는 겁니다.

```bash
cd ../surf-brief
pip install -r requirements.txt
python3 surf_brief.py
```

상세 브리핑이 출력되면 성공입니다. 이제 **세 가지를 눈으로 확인**해주세요.

| 확인할 것 | 안 맞으면 |
|---|---|
| **파고·너울 수치가 윌리웨더와 비슷한가** | 모델이 달라 수십 cm 차이는 정상. 배 이상 차이 나면 알려주세요 |
| **만조·간조 시각이 맞는가** | `물때: 조위 데이터 없음` 이 뜨면 다른 조석 소스를 붙여야 합니다 |
| **포인트 위치가 맞는가** | 좌표가 추정값입니다. 구글 지도에서 실제 진입 지점을 우클릭해 좌표를 알려주세요 |

카카오톡으로도 받아보세요.

```bash
python3 surf_brief.py --send
```

**여기까지 통과해야 4부로 넘어갈 가치가 있습니다.** 뭔가 이상하면 그 상태로
알려주세요 — 고치고 나서 진행하는 게 맞습니다.

## 4부. 클라우드 설정

등록할 값을 먼저 뽑습니다.

```bash
cd ../kakao-notify
python3 kakao_auth.py --show-env
```

두 줄이 출력됩니다. 그대로 복사해두세요.

이제 [claude.ai/code](https://claude.ai/code) 에서:

1. **메시지 입력창 바로 위 줄**의 환경 이름 버튼 (처음이면 `Default`)
2. 환경 위에 마우스를 올리면 오른쪽에 나타나는 **톱니바퀴 아이콘**
3. 다이얼로그에서 두 가지를 설정

**Network access** — `Trusted` → **`Custom`** 으로 바꾸고 도메인 4개 추가

```
marine-api.open-meteo.com
api.open-meteo.com
kauth.kakao.com
kapi.kakao.com
```

**Environment variables** — 방금 복사한 두 줄 붙여넣기

```
KAKAO_REST_API_KEY=...
KAKAO_REFRESH_TOKEN=...
```

> **주의.** 공식 문서는 클라우드 환경변수에 자격증명을 넣지 말라고 합니다
> (비밀 저장소가 따로 없음). 이 토큰은 권한이 `talk_message` 하나뿐이라
> 유출돼도 본인에게 카톡을 보내는 것 외에는 못 하지만, 그래도 두고 싶지
> 않으시면 4·5부를 건너뛰고 **컴퓨터의 cron/작업 스케줄러**로 돌리셔도 됩니다.
> 그 경우 매일 아침 컴퓨터가 켜져 있어야 합니다.

저장 후 **새 세션을 시작**하세요. 이미 떠 있는 컨테이너에는 환경 변경이
반영되지 않을 수 있습니다.

## 5부. 자동 실행 걸기

새 세션에서 이 브랜치로 들어와 점검부터 돌립니다.

```bash
cd tools/surf-brief && python3 selfcheck.py
```

도메인 4개, API 응답, 브리핑 생성, 카카오 인증을 순서대로 확인합니다.
전부 통과하면 Claude에게 말씀하세요.

> "브리핑 Routine 만들어줘"

이때 **출발지**를 같이 알려주세요. 브리핑 도착 시각이 달라집니다.

- **저비스 베이 근처** → 새벽 4시 발송 (준비하고 나가실 시간)
- **시드니에서 출발** → 전날 저녁 8시 발송 (새벽 3시에 나서야 하므로 당일 아침은 늦음)

## 막혔을 때

| 증상 | 해결 |
|---|---|
| `KOE006` | 1부 4번 Redirect URI가 `.env`와 다릅니다 |
| `KOE205` | 1부 5번 동의항목이 꺼져 있습니다 |
| 포트 5000 사용 중 | macOS는 AirPlay가 씁니다. 시스템 설정에서 끄거나 `--manual` 사용 |
| `조위 데이터 없음` | 그 좌표에 조석 데이터가 없습니다. 물때만 빠지고 나머지는 동작합니다 |
| `selfcheck` 도메인 실패 | 4부 Network access가 `Custom`인지, 새 세션인지 확인 |

각 도구의 자세한 설명은 [`kakao-notify/README.md`](kakao-notify/README.md) 와
[`surf-brief/README.md`](surf-brief/README.md) 에 있습니다.
